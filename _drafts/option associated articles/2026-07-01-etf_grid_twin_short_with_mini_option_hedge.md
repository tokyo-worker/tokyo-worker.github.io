# ETFサヤ取りグリッドトレード＋ミニオプション・ヘッジ戦略の理論
### Theoretical Minimum

> **本稿の位置付け．** 本戦略は，同一原指数（日経平均株価）に連動するレバレッジETF（1570）とダブルインバースETF（1459）を同時に空売りする「ツイン・ショート・グリッドトレード」と，日経225ミニオプションのアウト・オブ・ザ・マネー（OTM）両側買い（ロング・ストラングル）を組み合わせた複合ヘッジ戦略である．
> 
> グリッドの利益源はレバレッジ型ETF固有の「ボラティリティ減価（Volatility Decay）」にあり，ミニオプション買いはその弱点である一方向トレンド発生時の無制限損失リスクを限定するカタストロフィ・ヘッジとして機能する．
> 
> 本稿はその数理的基礎，グリーク動態，損益の確率統計的評価を self-contained に提示し，楽天RSS（マーケットスピードII）を用いた実務的実装への接続点を明示する．

## 1. ポジションの数理的俯瞰と境界条件

### 1.1 満期損益関数の定義と中心命題

本複合戦略は，以下の2つのサブ戦略から構成される．

**サブ戦略A：ツイン・ショート・グリッド（ETF空売りペア）**

時刻 $t$ において，1570を $n_L$ 株，1459を $n_I$ 株それぞれ空売りし，レシオ $R_t = P^{(L)}_t / P^{(I)}_t$（$P^{(L)}_t$：1570株価，$P^{(I)}_t$：1459株価）がグリッド幅 $\delta$ だけ変動した際に決済する．1往復（仕掛け→利確）の純利益は，

{% raw %}
$$\boxed{\Pi_{\text{Grid}} = \delta \cdot \left( n_L \cdot \bar{P}^{(L)} + n_I \cdot \bar{P}^{(I)} \right) - C_{\text{cost}}}$$
{% endraw %}

ここで $\bar{P}^{(L)},\, \bar{P}^{(I)}$ は仕掛け時の平均建値，$C_{\text{cost}}$ は貸株料・スプレッドコストの合計である．

*すなわち，グリッド幅（レシオの変動率）に建玉金額を掛けた金額から，ポジション保有中に発生するコストを差し引いた値が1往復の純利益となる．*

> **含意1（利益の源泉）．** 1570と1459は，日経平均が上下を繰り返す（ボックス相場）際に，複利効果によりいずれも元の水準より低下する「ボラティリティ減価（Volatility Decay）」という数学的性質を持つ．ツイン・ショートはこの減価現象そのものを収益源とする．
>
> **含意2（有利な相場）．** 日経平均が明確な方向感を持たず，毎日一定の範囲で乱高下するレンジ相場が最も有利である．ボラティリティが高いほどグリッドの回転率（約定回数）が増加し，かつ減価の速度も加速する．
>
> **含意3（不利な相場）．** 日経平均が一方向に連続上昇（または連続下落）するトレンド相場では，1570ショート（上昇時）または1459ショート（下落時）の含み損が急拡大する．これがサブ戦略Bのヘッジ対象リスクである．

---

**サブ戦略B：ミニオプション・ロング・ストラングル（OTM両側買い）**

現在の日経平均水準 $S_0$ に対して，行使価格 $K_C$（$K_C > S_0$）のコールと $K_P$（$K_P < S_0$）のプットをミニオプション（乗数100倍）で各1枚購入する（ロング・ストラングル）．

{% raw %}
$$\boxed{\Pi_{\text{Option}}(S_T) = 100 \cdot \max(S_T - K_C,\, 0) + 100 \cdot \max(K_P - S_T,\, 0) - 100 \cdot (C_{\text{call}} + C_{\text{put}})}$$
{% endraw %}

ここで $S_T$ は満期時の日経平均SQ値，$C_{\text{call}}$，$C_{\text{put}}$ はそれぞれコール・プットのプレミアム（単位：円）である．

*ブレイクイーブンは上側で $S_T = K_C + C_{\text{call}} + C_{\text{put}}$，下側で $S_T = K_P - C_{\text{call}} - C_{\text{put}}$ となる．その内側では保険料分が純コストとなり，外側に抜けた場合にグリッドの損失を相殺・補填する．*

> **定理（複合戦略の損益構造）．**
>
> **含意1（相互補完性）．** グリッドの利益関数はレンジ相場で正，トレンド相場で負となる一方，オプションの利益関数はトレンド相場（大幅な価格変動時）で正，レンジ相場でゼロ以下となる．両者は損益の凸性が逆向きであり，組み合わせることで「レンジでも生き残り，トレンドでも死なない」構造が実現される．
>
> **含意2（コスト構造）．** オプション買いのプレミアムは，週次ウィークリー限月のファー・アウト（ΔOTMが5〜15程度）を選ぶことで1セットあたり1,000〜3,000円程度に抑えられる．これがグリッドの週次期待利益を下回る限り，複合戦略全体の期待収益は正を維持する．

### 1.3 ギリシャ指標の多次元動態

本複合戦略のネット・グリーク（オプション部分）を整理する．ロング・ストラングル（コール買い＋プット買い）の各グリークは以下の通りである．

**ネット・グリーク（1セット：コール1枚＋プット1枚）**

| グリーク | 符号 | 意味 |
|:---|:---|:---|
| ネット・デルタ $\Delta_{net}$ | ≈0（対称時），ITMに近い方が優勢 | 原資産の価格変動に対する感応度 |
| ネット・ガンマ $\Gamma_{net}$ | **正（ロング）** | 価格変動が大きいほどデルタが有利方向に増大 |
| ネット・ベガ $\mathcal{V}_{net}$ | **正（ロング）** | IVが上昇するとポジション価値が増加 |
| ネット・セータ $\Theta_{net}$ | **負（タイム・ディケイ）** | 時間の経過とともに毎日価値が目減り |

**3軸動態マトリクス**

| グリーク | Moneyness（OTM→ATM→ITM） | 残日数（T→0） | IV（低→高） |
|:---|:---|:---|:---|
| デルタ $\Delta$ | OTM≈0, ATM≈±0.5, ITM≈±1へ収束 | OTMでは0へ急収束，ITMでは±1へ収束 | IV↑でATMデルタはほぼ不変，OTMデルタが拡大 |
| ガンマ $\Gamma$ | ATM近辺で最大化，OTMで急低下 | 満期近づくとATM付近で急峻化（ガンマ爆発） | IV↑でガンマ曲線がフラット化（全体に広がる） |
| ベガ $\mathcal{V}$ | ATM近辺で最大，OTMで急低下 | 残日数減少とともに逓減 | IVの水準自体がプレミアムに直接影響 |
| セータ $\Theta$ | ATM近辺で最大（目減り最大），OTMで小 | **満期直前に加速（セータ爆発）** | IV↑でセータも増大（プレミアムが大きいほど目減りも大） |

> **重要：** 本戦略でファー・OTMを選ぶ理由は，セータ（日々の目減り）を最小化するためである．プレミアムが安い（5〜10円程度）ファー・OTMのウィークリー限月は，1週間の保有コストが500〜1,000円（×100倍）に抑えられる一方，大暴走時（±5%超）には大きくレバレッジがかかる非対称性が生まれる．

### 1.4 ポジションの応用系と動的ヘッジ

**ガンマスキャルピングとの関係**

ロング・ストラングルはネット・ガンマが正であるため，理論上は原資産の価格変動のたびにデルタをニュートラルに戻す「ガンマスキャルピング」を行うことで，IVが実現ボラティリティを下回っていても利益を得られる．しかし本戦略ではETF側のグリッドが実質的に「自動化されたガンマスキャルピング代替機能」を果たしており，オプションのデルタヘッジは行わない（コスト増加のため）．

**ロール戦略**

ウィークリー限月のオプションはSQ（毎週の権利行使決済日）を通過するたびに再購入が必要である．以下のロール基準を採用する：

- **ロール・タイミング：** 木曜日の大引け後（翌週の限月が発行される当日）に再購入
- **ストライク選択：** 当週SQ後の日経平均終値を基準に，コール・プットそれぞれ約5%（±2,500円程度）離れた行使価格を選択
- **ロール中止基準：** グリッド側で当週の保険料（プレミアム合計）を上回る利益が確認できない週は，翌週のオプション購入を見送りコストを節約する

**一方向トレンド発生時のポジション調整**

日経平均が3日連続で同一方向に2%以上動いた場合，トレンド確認とみなし：
1. 当日以降の新規グリッド仕掛けを一時停止
2. 損失拡大中の含み損ポジション（1570ショートまたは1459ショート）の損切り水準を確認
3. ミニオプションのITM化による利益で損切りコストを相殺

## 2. 投資方程式と統計的評価

### 2.1 最大利益・最大損失・平均損益の代数的導出

**グリッド部分**

1往復の純利益 $\pi_{\text{grid}}$ の期待値は，1日のグリッド約定回数 $N$ と1往復あたりの純利益 $\pi_1$ で表される：

{% raw %}
$$E[\Pi_{\text{grid}}^{\text{day}}] = E[N] \cdot \pi_1 = E[N] \cdot \left(\delta \cdot (n_L \bar{P}^{(L)} + n_I \bar{P}^{(I)}) - C_{\text{cost}}\right)$$
{% endraw %}

約定回数 $N$ は，レシオの日次変動量 $\Delta R \sim N(0, \sigma_R^2)$ をグリッド幅 $\delta$ で割った往復数に概算でき，

{% raw %}
$$E[N] \approx \frac{2\sigma_R\sqrt{252}}{\delta\sqrt{252}} \cdot \sqrt{\frac{T_{\text{day}}}{\text{秒}}} \cdot f_{\text{monitor}}$$
{% endraw %}

ここで $f_{\text{monitor}}$ は監視頻度の実効因子（楽天RSSでは毎秒監視により高い捕捉率を実現）．

**グリッドの最大損失（無制限リスク）**

グリッドに損切りルールを設けない場合，日経平均が $\pm\Delta S$ 動いた時の最大損失は，

{% raw %}
$$\Pi_{\text{grid}}^{\min} \approx -2n_L \bar{P}^{(L)} \cdot \frac{\Delta S}{S_0} \quad \text{（上昇時：1570ショートの損失）}$$
{% endraw %}

これが理論上無制限であるため，ミニオプションによるヘッジが不可欠となる．

**オプション部分**

満期時の損益は式(2)の通りだが，ブレイクイーブンを代数的に導出する：

{% raw %}
$$\text{上側 BEP}: S_T^* = K_C + C_{\text{call}} + C_{\text{put}}$$
{% endraw %}

{% raw %}
$$\text{下側 BEP}: S_T^* = K_P - C_{\text{call}} - C_{\text{put}}$$
{% endraw %}

BEPの外側では線形にオプション利益が増大し，グリッドの損失を補填する．

### 2.2 各事象の発生確率の算定方法

ブラック–ショールズ模型を用いて，各シナリオの確率を算定する．

**コールのデルタ（≈原資産価格が満期にKCを超える確率のリスク中立近似）**

{% raw %}
$$P(S_T > K_C) \approx N(d_2), \quad d_2 = \frac{\ln(S_0/K_C) + (r - \sigma^2/2)T}{\sigma\sqrt{T}}$$
{% endraw %}

ここで $N(\cdot)$ は標準正規累積分布関数，$\sigma$ はIV，$T$ は残存期間（年換算）．

**プットのデルタ（下側を割る確率）**

{% raw %}
$$P(S_T < K_P) \approx N(-d_2^P), \quad d_2^P = \frac{\ln(S_0/K_P) + (r - \sigma^2/2)T}{\sigma\sqrt{T}}$$
{% endraw %}

**オプション最大損失確率（双方行使されない確率）**

{% raw %}
$$P(K_P \leq S_T \leq K_C) = N(d_2^C) - N(-d_2^P)$$
{% endraw %}

この確率が高いほど，オプションはプレミアム全額を失う（保険が不要な静穏な週）．

### 2.3 パラメータの最適化数理

**グリッド幅 $\delta^*$ の最適化**

期待収益 $E[\Pi_{\text{grid}}]$ は $\delta$ の関数であり，スプレッドコスト $c_s$ と約定回数のトレードオフで最大化される：

{% raw %}
$$\delta^* = \arg\max_{\delta} \left[ \frac{\sigma_R \sqrt{T_{\text{day}}}}{\delta} \cdot (\delta \cdot V - c_s) \right] = \arg\max_{\delta} \left[ \sigma_R\sqrt{T_{\text{day}}} \cdot V - \frac{c_s \sigma_R \sqrt{T_{\text{day}}}}{\delta} \right]$$
{% endraw %}

ここで $V = n_L \bar{P}^{(L)} + n_I \bar{P}^{(I)}$ は建玉金額合計．$\delta$ を小さくするほど利確頻度が増えるが，1往復あたりの純利益も減る．実務的には **$\delta^* \approx \max(3 c_s / V,\; 0.002)$** が目安となる（コストの3倍以上の利幅を確保）．

**行使価格の最適選択**

OTMのデルタ $\Delta_{OTM}$ が5〜15（5〜15%の行使確率）の範囲に入るストライクを選ぶ：

{% raw %}
$$K_C^* = S_0 \exp\left(\sigma\sqrt{T} \cdot N^{-1}(1 - \Delta_{\text{target}}) - (r - \sigma^2/2)T\right)$$
{% endraw %}

週次（$T \approx 5/252$）かつ $\sigma = 0.25$（年率25%），$\Delta_{\text{target}} = 0.10$ とすると，$K_C^* \approx S_0 \times 1.042$（現水準の約4.2%上）が目安となる．

### 2.4 注文執行・手じまいのアルゴリズム

#### 【構築フェーズ】グリッド発注アルゴリズム

```
【毎秒実行ループ】
Step 1: 板情報取得
  R_bid = RssMarket("1570.T", "最良買気配値段")
         / RssMarket("1459.T", "最良買気配値段")  ← 両方空売り時のレシオ
  R_ask = RssMarket("1570.T", "最良売気配値段")
         / RssMarket("1459.T", "最良売気配値段")  ← 買い戻し時のレシオ

Step 2: 発注条件チェック
  If ABS(R_bid - R_entry[k]) >= δ AND 板厚チェックOK
  AND 現在時刻 < 14:55
  AND 未決済グリッド数 < 最大グリッド数
  Then → Step 3

Step 3: 同時発注（ペア注文）
  RssOrder(銘柄="1570.T", 区分=信用売, 数量=n_L, 種別=指値,
           値段=R_bid * 1459板値)
  RssOrder(銘柄="1459.T", 区分=信用売, 数量=n_I, 種別=指値,
           値段=1459の最良買気配値段)
  R_entry[k] = R_bid   ← エントリーレシオを記録

Step 4: 片肺チェック（5秒後）
  If 1570のみ約定 AND 1459未約定:
    1570を即座に買い戻す（損切り）
```

#### 【決済フェーズ】利確・損切りアルゴリズム

```
Step 5: 利確条件
  If R_ask <= R_entry[k] - δ（レシオが δ 分縮小）:
    1570を買い戻し（指値：最良売気配値段）
    1459を買い戻し（指値：最良売気配値段）
    利益確定

Step 6: 損切り条件（安全弁）
  If R_bid >= R_entry[k] + 5δ（5グリッド分逆行）:
    全ポジションを成行で損切り
    新規グリッド発注を30分停止
```

#### 【オプション・ヘッジフェーズ】週次手動処理

```
毎週月曜日 09:30 実行:
Step H1: ウィークリー限月の確認
  翌金曜日SQ日を確認

Step H2: ストライク選択
  S0 = 日経225の現在値
  K_C = S0 * 1.04 以上で最近傍の250円刻みストライク
  K_P = S0 * 0.96 以下で最近傍の250円刻みストライク

Step H3: プレミアム確認
  If C_call + C_put <= グリッド想定週次利益 * 0.3:
    コール1枚・プット1枚を指値で購入（最良売気配値段付近）
  Else:
    今週はヘッジ購入見送り（コスト超過）

Step H4: SQ通過後（金曜日午前10時以降）
  古いポジションの損益を確定
  翌週分の購入へ → Step H1 へ戻る
```

## 3. 設例：完全トレース可能な数値計算とRSS実装

### 3.1 初歩的数値例

**データ基準日：2026年7月1日（火）**

本日の市場実勢データ（2026年6月30日終値・直近参照値）：
- 日経平均株価：約 **70,000円**（2026年6月下旬の実勢水準；注記参照）
- 1570（NEXT FUNDS 日経レバ）：**79,510円**（2026年6月30日取引値）
- 1459（楽天Wベア日経ダブルインバース）：**約106円**（年初来安値96円，2026年6月15日水準調整実施後）
- 日経225IV（インプライド・ボラティリティ）：**約25%**（年率；2026年6月水準を仮定）

> **注記：** 1459は2026年6月15日に指数水準調整（2桁引き上げ）を実施しており，株価の絶対値は調整後の水準を使用する．

---

**【設定パラメータ】**

| 項目 | 値 | 備考 |
|:---|:---|:---|
| 1570 建値 $\bar{P}^{(L)}$ | 79,510円 | 2026/6/30終値 |
| 1459 建値 $\bar{P}^{(I)}$ | 106円 | 推定値（水準調整後） |
| 初期レシオ $R_0$ | 79,510 ÷ 106 ≈ **750** | |
| 1570 売り株数 $n_L$ | 1株 | |
| 1459 売り株数 $n_I$ | 750株 | 投資金額を均等化：1570×1株≈79,510円，1459×750株≈79,500円 |
| グリッド幅 $\delta$ | 0.003（0.3%） | レシオが0.3%変動で1グリッド発動 |
| 貸株料（年率） | 2.5% | 楽天証券一般信用売り標準 |
| ミニオプション コール行使価格 $K_C$ | 73,000円 | 日経平均+4.3%（約250円刻み） |
| ミニオプション プット行使価格 $K_P$ | 67,000円 | 日経平均−4.3% |
| コール・プレミアム $C_{\text{call}}$ | 8円（推定） | ΔOTMが10程度のファー・OTM |
| プット・プレミアム $C_{\text{put}}$ | 7円（推定） | 同上 |

---

**【ステップバイステップ計算：1往復のグリッド利益】**

**Step 1：建玉金額の確認**

{% raw %}
$$V = n_L \cdot \bar{P}^{(L)} + n_I \cdot \bar{P}^{(I)} = 1 \times 79{,}510 + 750 \times 106 = 79{,}510 + 79{,}500 = 159{,}010 \text{ 円}$$
{% endraw %}

**Step 2：グリッド1往復の粗利益**

{% raw %}
$$\text{粗利益} = \delta \cdot V = 0.003 \times 159{,}010 \approx \mathbf{477 \text{ 円}}$$
{% endraw %}

**Step 3：コストの算出（1日保有を想定）**

貸株料（日割り）：

{% raw %}
$$C_{\text{貸株}} = V \times \frac{0.025}{252} = 159{,}010 \times 0.0000992 \approx \mathbf{16 \text{ 円/日}}$$
{% endraw %}

スプレッドコスト（両銘柄の往復：片道1円の仮定）：

{% raw %}
$$C_{\text{スプレッド}} = (n_L \times 1) \times 2 + (n_I \times 0.01) \times 2 = 2 + 15 = \mathbf{17 \text{ 円}}$$
{% endraw %}

**Step 4：1往復の純利益**

{% raw %}
$$\boxed{\pi_1 = 477 - 16 - 17 = \mathbf{444 \text{ 円 / 1往復}}}$$
{% endraw %}

---

**【ステップバイステップ計算：ミニオプション保険料コスト（週次）】**

**Step 5：オプション購入コスト**

{% raw %}
$$C_{\text{option/週}} = (C_{\text{call}} + C_{\text{put}}) \times 100 \text{（乗数）} = (8 + 7) \times 100 = \mathbf{1{,}500 \text{ 円/週}}$$
{% endraw %}

（楽天証券手数料19.8円/枚×2枚 = 約40円を加算すると合計 **1,540円/週**）

**Step 6：ブレイクイーブン（週次）の算出**

グリッドが週に何往復約定すれば保険料を回収できるか：

{% raw %}
$$N_{\text{BEP}} = \frac{C_{\text{option/週}}}{\pi_1} = \frac{1{,}500}{444} \approx \mathbf{3.4 \text{ 往復}}$$
{% endraw %}

日経平均のボラティリティが25%（年率）の場合，日次の変動率は約 $25\%/\sqrt{252} \approx 1.57\%$ である．レシオの変動はこれに連動し，1日あたりの理論グリッド往復数は：

{% raw %}
$$E[N/\text{日}] \approx \frac{2 \times 1.57\%}{0.3\%} \times \text{捕捉効率} \approx 5 \times 0.6 = \mathbf{3 \text{ 往復/日}}$$
{% endraw %}

5営業日で **15往復** が期待値となり，保険料（3.4往復分）を差し引いた **11.6往復 × 444円 ≈ 5,150円/週** が純利益の目安となる．

**【シナリオ別損益確認】**

| シナリオ | 日経平均の動き | グリッド損益 | オプション損益 | 合計 |
|:---|:---|:---|:---|:---|
| ① 平穏なレンジ | 週±1%未満 | +3,000円 | −1,540円（消滅） | **+1,460円** |
| ② 適度なうねり | 週±2%の往復 | +6,650円 | −1,540円（消滅） | **+5,110円** |
| ③ 一方向急騰 | 週+10%（+7,000円） | −12,000円 | +30,000円超 | **+18,000円超** |
| ④ 一方向急落 | 週−10%（−7,000円） | −12,000円 | +30,000円超 | **+18,000円超** |

### 3.2 応用設例：シナリオ分析

**③④の急騰・急落時のオプション損益（詳細計算）**

日経平均が満期時に $S_T = 77,000$（+10%上昇）となった場合：

コールが行使される（$S_T = 77,000 > K_C = 73,000$）：

{% raw %}
$$\Pi_{\text{call}} = 100 \times (77{,}000 - 73{,}000) - 100 \times 8 = 400{,}000 - 800 = \mathbf{399{,}200 \text{ 円}}$$
{% endraw %}

プットは権利消滅（$S_T > K_P$）：

{% raw %}
$$\Pi_{\text{put}} = -100 \times 7 = \mathbf{-700 \text{ 円}}$$
{% endraw %}

オプション純利益：

{% raw %}
$$\boxed{\Pi_{\text{option}} = 399{,}200 - 700 = \mathbf{398{,}500 \text{ 円}}}$$
{% endraw %}

（グリッドで最大−50,000円程度の損失が発生したとしても，オプションが完全に補填して余りある）

### 3.3 楽天RSSを用いたトレーディング環境の実装設計

楽天RSS（マーケットスピードII）のDDE関数を用いたExcelシートの設計図を以下に示す．

**シート構成（推奨）**

```
【シート1：リアルタイム板情報モニター】
-------------------------------------------
セル配置：

A1 =RssMarket("1570.T","最良買気配値段")   ← 1570 最良買気配（空売り時の約定想定価格）
A2 =RssMarket("1570.T","最良売気配値段")   ← 1570 最良売気配（買戻し時の約定想定価格）
A3 =RssMarket("1570.T","最良買気配数量")   ← 板厚確認（自注文量と比較）

B1 =RssMarket("1459.T","最良買気配値段")   ← 1459 最良買気配
B2 =RssMarket("1459.T","最良売気配値段")   ← 1459 最良売気配
B3 =RssMarket("1459.T","最良買気配数量")   ← 板厚確認

C1 =A1/B1   ← 仕掛けレシオ（Bid/Bid）
C2 =A2/B2   ← 返済レシオ（Ask/Ask）
C3 =RssMarket("998407.O","現在値")         ← 日経平均現在値（SQ判断に使用）

D1 =NOW()   ← 現在時刻（時間フィルター用）
D2 =IF(HOUR(D1)*100+MINUTE(D1)>=1455,"停止","稼働")  ← 14:55以降に新規停止
```

```
【シート2：グリッド管理テーブル】
-------------------------------------------
列:  A        B         C          D       E         F
行1: グリッドNo  仕掛け日時  仕掛けレシオ  1570建値  1459建値   状態
行2: 1        [自動入力]  [C1コピー]   [A1コピー] [B1コピー]  "未決済"
行3: 2        ...       ...         ...       ...        ...
行N: ...

G1: 利確目標レシオ  =C2 - 対応D行のδ  ← 利確判定の基準

【グリッド監視マクロ（VBA擬似コード）】
Sub GridMonitor()
  Dim δ As Double: δ = 0.003
  Dim n_L As Long: n_L = 1
  Dim n_I As Long: n_I = 750

  ' 毎秒ループ
  Do While True
    Dim R_bid As Double
    Dim R_ask As Double
    R_bid = Range("C1").Value   ' 仕掛けレシオ
    R_ask = Range("C2").Value   ' 返済レシオ

    ' ① 時間フィルター
    If Range("D2").Value = "停止" Then GoTo NextLoop

    ' ② 利確チェック（全グリッド）
    For k = 2 To 最終グリッド行
      Dim R_entry As Double
      R_entry = Cells(k, 3).Value   ' C列：仕掛けレシオ
      If Cells(k, 6).Value = "未決済" Then
        If R_ask <= R_entry - δ Then
          ' 利確注文発行
          Call RssOrderWrapper("1570.T", "買", n_L, "指値", Range("A2").Value)
          Call RssOrderWrapper("1459.T", "買", n_I, "指値", Range("B2").Value)
          Cells(k, 6).Value = "決済済"
        End If
        ' ③ 損切りチェック（5グリッド逆行）
        If R_bid >= R_entry + 5 * δ Then
          Call RssOrderWrapper("1570.T", "買", n_L, "成行", 0)
          Call RssOrderWrapper("1459.T", "買", n_I, "成行", 0)
          Cells(k, 6).Value = "損切"
        End If
      End If
    Next k

    ' ④ 新規グリッド発注チェック
    If 未決済グリッド数 < 最大グリッド数 Then
      If ABS(R_bid - 直近エントリーレシオ) >= δ Then
        If Range("A3").Value >= n_L And Range("B3").Value >= n_I Then
          Call 新規グリッド発注(R_bid, n_L, n_I)
        End If
      End If
    End If

    NextLoop:
    Application.Wait Now + TimeValue("00:00:01")  ' 1秒待機
  Loop
End Sub
```

```
【シート3：オプション管理（週次）】
-------------------------------------------
E1: =RssMarket("998407.O","現在値")     ← 日経平均現在値
E2: =E1 * 1.04                         ← コール推奨行使価格（目安）
E3: =E1 * 0.96                         ← プット推奨行使価格（目安）
E4: 週次保険料予算 = グリッド週次期待利益 * 0.30   ← 手動入力

【オプション損益計算（SQ時）】
F1: 入力：SQ値
F2: コール損益 =IF(F1>G1,(F1-G1)*100-H1*100,-H1*100)
     G1：コール行使価格，H1：コール購入プレミアム
F3: プット損益 =IF(F1<G2,(G2-F1)*100-H2*100,-H2*100)
     G2：プット行使価格，H2：プット購入プレミアム
F4: オプション合計損益 =F2+F3
```
